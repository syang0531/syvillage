# V2 — 보류 중인 설계

> ## ⛔ 이 문서의 내용은 구현 대상이 아니다
>
> V1 작업 중에 여기 있는 것을 만들지 않는다. 좋은 뜻이라도 안 된다.
>
> 이 문서의 목적은 두 가지다. (1) V1에 남겨야 할 **훅**을 알려준다. (2) V1 설계가 V2를 막지 않는지 확인한다.

---

## V1에 반드시 남겨야 할 훅

이것만이 V1의 작업 범위다. 전부 M0에서 넣는다.

| 훅 | 위치 | V1 동작 |
|---|---|---|
| `Settlement.ruler` | `data/Settlement.java` | 항상 `Ruler.Npc(촌장 UUID)`. 아무 일도 하지 않음 |
| `Ruler` sealed interface | `data/Ruler.java` | `Npc`만 사용. `Player` 변형은 정의만 |
| `canPromoteToLordship(Settlement)` | `sim/ScaleModule.java` | 항상 `false` 반환하는 빈 함수 |
| `Settlement.parentId` (UUID, nullable) | `data/Settlement.java` | 항상 `null` |
| 이주 경로 | `sim/PopulationModule.java` | 정주지 간 인구 이동. V2 물류·징집이 이 경로를 재사용 |

자리를 비워두는 것과 나중에 뚫는 것은 차이가 크다. 특히 `ruler`와 `parentId`는 `Codec`과 저장 포맷에 영향을 주므로 나중에 추가하면 마이그레이션이 필요해진다.

## 축 2 — 지위

V1의 축1(규모)이 인구로 **자동 성장**하는 것과 달리, 축2는 **플레이어가 앵커 블록을 지어야만** 올라간다. 여기가 성능 상한이자 의사표현 지점이다.

| 지위 | 앵커 블록 | 요구 조건 | 얻는 것 |
|---|---|---|---|
| 무소속 | — | — | 완전 바닐라 |
| 영지 | 영주의 탁자 | 종 1, 침대 8, 주민 5 | 클레임, 시뮬 시작 |
| 백작령 | 성주의 옥좌 | 규모 ≥ 읍, 종속 영지 2 | 징집, 물류, 방위 |
| 공작령 | 대공의 인장 | 규모 ≥ 도시, 종속 백작령 2 | 광역 세금, 상비군 |
| 왕국 | 왕좌 | 종속 공작령 2 + 대관식 | 외교, 선전포고 |

### 두 축은 독립이다

주민 50명짜리 도시가 정치적으로는 남의 영지일 수 있고, 주민 6명뿐인 촌락이 왕국의 수도일 수도 있다(몰락한 왕가). 티어를 하나로 합치면 이런 것이 전부 불가능해진다.

### 종과 앵커의 역할 분담

V1에서 종이 마을 등록을 담당하지만, V2에서 종을 앵커로 쓰면 안 된다.

- **종** — 물리적 중심. 집합 지점, 경보 장치. 여러 개 가능
- **영주의 탁자** — 행정 중심. 데이터 레코드의 앵커. 마을당 정확히 하나

종을 앵커로 쓰면 월드의 모든 바닐라 마을이 자동 승격되어 성능 상한이 사라진다. 대신 **종을 승격 전제조건으로** 쓴다.

구조물 스캔으로 "이게 촌장집인가"를 판정하지 않는다. 커스텀 블록 하나로 환원한다.

### 중복 방지

기존 클레임 반경 안에는 앵커 배치 불가. 이 한 줄이 마을 간 최소 간격과 플레이어 간 완충지대를 동시에 보장한다.

---

## 왕국은 그래프다

정치 관계를 "플레이어 대 NPC"로 보지 않는다. **정주지 노드 + 봉신 엣지**다. 통치자는 노드의 속성일 뿐이고, 플레이어든 NPC든 같은 타입 자리에 들어간다.

```java
record Realm(UUID id, UUID capital, Ruler ruler, List<UUID> vassals) {}
```

왕국의 영역을 사각형으로 정의하지 않는다. **소속 영지 목록**이고, 지도상 영역은 자식들의 합집합이다. 왕국이 지리적으로 찢어져 있어도 자연스럽고, 반란은 리스트에서 빠지는 일이 된다.

### 통치자는 기본적으로 NPC

플레이어가 왕좌를 짓고 초대 왕을 세우지만, 그 뒤로 왕국은 스스로 굴러간다. 플레이어가 직접 왕관을 쓰는 것도 허용하되 **부재 시 섭정 NPC가 대리**한다.

플레이어를 왕으로 고정하면 로그아웃 시 왕국이 멈춰야 하고, V1에서 공들인 가상 시뮬이 의미를 잃는다.

## 충성 서약

메뉴 버튼이 아니라 **물건이 관계를 매개한다.** 뺏길 수도 건넬 수도 있어야 한다.

**서약 증서** — 종주 측에서만 제작. 자기보다 한 단계 낮은 지위에 대해서만 발행 가능. 이 제약 하나로 위계가 자동으로 지켜진다. 사용은 상대 정주지의 **영주의 탁자에 우클릭**.

### 봉신이 되는 세 경로

1. **창설** — 플레이어가 직접 세운 마을은 절차 없이 처음부터 봉신
2. **자발적 서약** — 증서 제시 + 수락 판정 통과
3. **정복** — 전쟁 승리 후 강제 서약. 즉시 성사되나 **충성도 0에서 시작**

### NPC 수락 판정

| 요소 | 방향 |
|---|---|
| 주변 위협도 | + |
| 종주 명성 (군사력, 영토, 방위 실적) | + |
| 바친 공물 | + |
| 영주 자립심 (규모에 비례) | − |
| 거리 | − |
| 원한 (전쟁·약탈 이력) | − |

거절당했을 때 할 수 있는 것이 명확해지는 게 이 표의 목적이다. 공물 추가, 습격 대신 격퇴(명성↑ 원한↓), 군사력 증강, 또는 침공.

작은 마을은 쉽게 굽히고 도시는 거의 안 굽히므로 **자연스러운 성장 경로**가 생긴다.

### 플레이어 간

증서를 건네거나 상대 왕좌에 놓으면 제안이 걸리고, 상대가 우클릭으로 수락. 조건(세율, 최소 존속 기간, 파기 위약금)을 증서에 각인 가능.

오프라인이면 증서가 꽂힌 채 대기하고 접속 시 알림. 섭정 NPC의 대리 수락은 **기본 꺼짐**.

## 서약이 주는 것

이게 없으면 색깔놀이다. 최소 네 가지.

| 기능 | 내용 |
|---|---|
| 세금 | 봉신 생산의 일정 비율이 종주 창고로. L2 물류로 처리, 실제 운송 없음 |
| 징집 | 전쟁 시 봉신 병력 소집. 봉신에겐 손실이므로 충성도와 직결 |
| 방위 | 봉신 습격 시 종주 병력 출병. **가장 중요.** 자발적 서약의 동기 |
| 청사진 공유 | 상위 티어 건물 템플릿 해금 |

## 충성도

봉신 엣지에 **스칼라 하나**만 붙이면 나머지가 굴러간다. L3에서도 숫자 하나라 비용이 없다.

```
loyalty += 방위 성공, 선물, 낮은 세율, 종주 명성 상승
loyalty -= 높은 세율, 방위 실패, 징집 손실, 종주 약화, 거리
```

임계값 아래로 내려가면 독립 선언. **예고 없이 터지면 안 된다.** 단계를 둔다: 불만(경고) → 동요(다른 종주 접근 중) → 반란.

플레이어의 자발적 파기는 언제든 가능하되 **명예 페널티**. 다른 NPC의 수락 판정에서 원한이 올라간다.

## L3 추상 티어 — AI 왕국

AI 왕국을 플레이어 왕국과 같은 해상도로 돌리면 성능 상한이 즉시 사라진다. 티어를 하나 더 내린다.

| 티어 | 저장하는 것 | 스텝 주기 |
|---|---|---|
| **L3 추상** | 왕국 스칼라 5~6개 (인구·부·군사·안정·관계) | 게임일 1회 |
| L2 가상 | 정주지·주민 레코드 | 10초 |
| L0 실제 | 엔티티 | 1틱 |

L3에는 마을 레코드조차 없다. 왕국 하나가 숫자 여섯 개다. 왕국 서른 개를 돌려도 비용이 사실상 0이다.

플레이어가 그 영역에 처음 접근하는 순간 **스칼라를 역산해 정주지와 주민을 생성**한다. 인구 340 → 마을 4개, 규모 분배, 주민 이름·나이·직업 생성. 한 번만 하고 이후 L2.

### 여기서 나오는 것

플레이어가 몇 달 만에 어느 지역에 가봤더니 **전쟁으로 폐허가 된 마을**이 있다. L3에서 전쟁 판정이 났고 실체화 시점에 결과가 지형에 반영된 것이다. 비용은 숫자 몇 개 굴린 게 전부다.

### 배치

월드 생성 시 시드 기반으로 2~4개. 이후 NPC 마을이 조건을 채우면 자체 승격 가능하되 **전역 상한**(기본 8).

### 미해결 과제

**L3 스칼라를 실제 마을로 역산하는 규칙**이 아직 정해지지 않았다. 이미 생성된 바닐라 마을 지형 위에 "이 왕국은 인구 340이었다"를 어떻게 얹을지가 관건이다.

## AI 의사결정

유틸리티 AI. 행동마다 점수 함수를 두고 최고점을 고른다.

```java
score(DeclareWar, target) =
      ruler.aggression * 0.4
    + (myMilitary / target.military - 1.0) * 0.3
    + borderPressure(target) * 0.2
    - stability * 0.3;
```

**통치자마다 성격 벡터**를 준다. 공격성·탐욕·신앙심·경계심 네 개면 충분히 다양해진다. 승계 시 부모 값에서 약간 흔들어 상속하면 왕조마다 색깔이 생긴다.

V1의 결정성 원칙이 그대로 적용된다. AI 결정은 `(상태, 성격, seed ^ realmId ^ simStep)`의 **순수 함수**여야 한다.

## 전쟁 — 가장 덜 설계됨

서약·반란·정복이 전부 "이겼다/졌다"를 전제하는데, 그 판정이 아직 구체화되지 않았다.

핵심 난제: L0에서는 실제 병사들이 싸우고 L3에서는 스칼라 비교인데, **둘이 같은 결과를 내도록 맞춰야 한다.** V1의 `defenseRating` 보정 절차(`docs/testing.md` 4절)와 같은 문제의 확대판이다.

V2 착수 시 이것부터 설계한다.
