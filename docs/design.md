# 설계 (V1 재정의)

이 문서는 2026-09-17에 기존 설계를 대체한다. 이전 문서들(`population.md`, `defense.md`, `simulation.md`, `architecture.md`)은 **더 이상 유효하지 않다.** 왜 갈아엎었는지는 `docs/why-the-reset.md`.

## 원래 문제로 돌아간다

> 밤에 몬스터가 주민을 죽인다. 어떻게 보호할 것인가.

이게 처음부터 진짜 문제였다. 이전 설계는 이걸 `RaidResolver`라는 **추상화로 옮겨서** 풀었다 — 확률과 방어 등급으로. 그동안 실제 몹은 성벽 안에서 계속 스폰됐다. **성벽은 빛을 만들지 않고, 스폰을 정하는 것은 밝기다.**

며칠을 습격 확률 튜닝에 썼는데 주민을 죽이던 것은 그 습격이 아니었다.

## 원칙

### 1. 바닐라를 건드리지 않는다

직업은 작업대가 정한다. 번식은 침대와 음식이 정한다. 죽음은 몹과 배고픔이 정한다. **우리는 그중 무엇도 대신 계산하지 않는다.**

주민 기록이 없다. `Resident`도, 나이도, 사기도, 배고픔도 없다. 주민은 그냥 바닐라 주민이다.

### 2. 우리가 하는 일은 건물을 짓는 것뿐이다

종으로 마을을 지정하면, 그 마을은 시간이 지나며 인프라를 쌓는다.

```
도로  →  가로등  →  밭  →  집
```

그게 전부다. 자원도 재고도 비용도 없다. **건설이 시간을 쓰는 것으로 충분하다.**

**밭이 가정의 나머지 절반이다.** 바닐라 번식은 주민이 음식을 들고 있어야 일어나고, 그 음식은 농부가 밀을 수확해 나눠준 것이다. 밭 없는 침대는 2세대가 없는 마을이다.

### 3. 인구는 시뮬레이션하지 않는다

침대가 생기면 바닐라가 번식시킨다. 밭이 생기면 바닐라가 먹인다. 빛이 생기면 몹이 안 나온다.

**인프라가 쌓이면 인구는 따라온다.** 우리가 셀 것이 없다.

### 4. 청크가 로드된 동안에만 짓는다

LOD가 없다. promote/demote가 없다. 정산 등가성도, replay도 없다.

안 가본 마을은 자라지 않는다. **자라는 것을 보는 게 재미고**, 그 대가로 L0/L2 경계가 사라진다 — 성벽 파이프라인 버그 일곱 중 여섯이 거기서 나왔다.

### 5. 월드에 놓는 것은 되돌릴 수 있어야 한다

플레이어가 부순 것은 다시 짓지 않는다. 우리가 놓은 블록은 `/placitum undo`로 전부 걷어낼 수 있다.

## 데이터

```java
record Settlement(
    SettlementId identity,   // id, 이름, 차원, 종 위치, 클레임 반경
    PlotGrid grid,           // 12블록 셀 격자 = 도시계획의 주기. 측량 결과
    Map<UUID, Plot> plots,   // 지어진 것
    List<BuildJob> queue,    // 짓는 중인 것
    Chronicle chronicle      // 무엇이 언제 지어졌는가
)
```

주민이 없으므로 `SavedData` 한 덩어리로 충분하다.

## 건설

여섯 단계는 그대로 쓸 만하므로 남긴다. `NEED → PLAN → QUEUE → EXECUTE → COMPLETE`.

- `NEED` — 다음에 무엇이 없는가 (**가로등 → 집/밭 → 도로**)
- `PLAN` / `QUEUE` — 지면을 읽고 `BuildRecipe`에 박제
- `EXECUTE` — 매 틱 `buildBlocksPerTick`개 블록. **손잡이는 하나뿐이다** — 간격과 배치 크기 두 개를 두었더니 예전 월드에 남아 있던 config가 간격을 10으로 되돌려서, 10틱마다 10블록 = 정확히 원래 속도가 나왔다
- `COMPLETE` — 플롯 등록, 셀 표시, 연대기

`expand(recipe)`는 여전히 **순수 함수**다. 이유는 바뀌었다 — replay 때문이 아니라, **같은 입력이 같은 건물을 내야 테스트할 수 있기** 때문이다.

## 도시계획 — 탐색 대신 산술

부지 선택은 **탐색**이었다. 빈 셀이고, 도로에 접했고, 중심에 가깝고, 충분히 평평한 곳. 그 탐색이 낸 버그는 전부 같은 모양이었다 — **한 조건에는 맞고 다른 조건에는 틀린 자리.** 비탈 18블록 아래의 집. 다른 집 지붕 위의 집. 지을 자리가 남지 않을 만큼 촘촘한 가로등.

계획은 그럴 수가 없다. 모든 좌표가 **종 위치의 함수**다.

```
주기(PERIOD) = 도로 3 + 여유 1 + 부지 7 + 여유 1 = 12

. . . | . | 부 부 부 부 부 부 부 | . |     부지 7x7
      ↑ 여유 1 (가로등)          ↑ 여유 1
      부지 안쪽 5x5만 건축물 (지붕·계단이 튀어나올 자리를 남긴다)
```

- **도로·가로등은 지형을 가리지 않는다.** 비탈의 마을에도 길은 있고, 빛이 스폰을 막는다
- **건축은 평지에서만.** 기울기가 `maxCellSlope`를 넘으면 그냥 안 짓고 기다린다. 지형을 깎지 않는다
- **기다리는 것은 포기가 아니다.** 플레이어가 나중에 평탄화하면 그 부지에 집이 선다. 명령어보다 나은 마을 유도 방법이다
- **집 문은 남/북.** 부지 사방이 도로이므로 접근성 문제가 아니라 **거리처럼 보이느냐**의 문제다. 각자 가까운 도로를 보는 문은 주차장처럼 보인다
- **없으면 짓고, 없을 게 없으면 아무것도 안 한다.** 당연해 보이지만 아니었다: 이전 버전은 도로를 다 깔고, 불을 켜고, 도로를 다시 깔았다
- **순서는 빛 → 건물 → 도로.** 빛이 원래 문제의 답이고, 도로는 블록 수가 압도적으로 많다. 도로를 먼저 두면 첫 집 전에 빈 도로 600블록을 깐다
- **아무것도 안 지을 때는 왜 안 짓는지 말한다.** `Lots.Verdict`가 부지마다 이유를 낸다 (taken / forbidden / unloaded / built_on / water / steep). "아무 일도 안 일어난다"는 관측에는 늘 설명이 둘 이상 있다

### 계획은 마을과 함께 넓어진다

`TownPlan.radius`는 **지어진 것 중 가장 바깥 고리 + 1**이다. 고정 반경이면 집 두 채짜리 마을이 150블록의 빈 도로와 가로등을 까느라 한참을 쓴다. 지어진 것에서 재므로 줄어들지 않는다.

## 가로등 — 실제 해법

클레임 안 밝기를 올려 **몹이 스폰을 못 하게** 한다. 이게 원래 문제에 대한 직접적인 답이다.

- **여유 칸이 교차하는 곳** — 즉 모든 부지의 네 모서리 — 에 울타리 기둥 2 + 랜턴을 세운다
- 부지 위에도, 도로 위에도 서지 않는다. 이전 버전의 실수가 그것이었다
- 물 위에는 세우지 않고, 이미 밝은 곳은 건너뛴다. 그래서 수렴한다
- `/placitum light`가 아직 어두운 기둥 자리를 말해준다

### 성벽은 짓지 않는다

세 가지 이유로 뺐다.

1. 스폰을 막는 것은 **빛**이지 벽이 아니다
2. 벽은 **고정된 링**이라 마을이 커지면 틀린 자리에 있게 된다
3. 1,600블록짜리 물건이 해결하는 것이 없었다

대가는 있다. 벽은 **밖에서 걸어 들어오는 몹**을 막는다. 가로등을 클레임보다 넓게 깔아 어두운 고리를 멀리 밀어내는 것으로 대신한다.

## 없앤 것

| | 왜 |
|---|---|
| `Resident` 전체 | 바닐라 주민이면 충분하다 |
| 생산·소비·기근 | 플레이어가 한 번도 만지지 않는 경제였다 |
| 수용력 공식 | 침대 수는 바닐라가 이미 센다 |
| 직업 배정 | 작업대가 정한다 |
| 습격·방어 등급 | 주민을 죽이던 것이 아니었다 |
| 성벽·성문 | 스폰을 막지 못하고, 마을이 커지면 틀린 자리에 남는다 |
| 노화사 | 바닐라에 없는 개념 |
| promote / demote / LOD | 가상화할 주민이 없다 |
| 자원 재고 | 건설 시간이 이미 비용이다 |

약 10,900줄에서 그 대부분이 사라진다.
