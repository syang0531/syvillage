# 왜 갈아엎었나

2026-09-17. M0~M3를 구현하고 게임에서 검증한 뒤, 설계를 되돌렸다. 무엇을 배웠는지 남긴다.

## 우리는 다른 문제를 풀었다

원래 문제는 이것이었다.

> 밤에 몬스터가 주민을 죽인다. 어떻게 보호할 것인가.

설계는 이 문제를 **방어 시뮬레이션**으로 옮겼다. 경보 상태 머신, 민병대, 장비 등급, 방어 등급, 습격 확률, 전리품 비율. 며칠을 `raidChancePerStep`과 `chanceToHold`를 튜닝하는 데 썼다.

그동안 **실제 몹은 성벽 안에서 계속 스폰됐다.** 성벽은 빛을 만들지 않고, 스폰을 정하는 것은 밝기다.

추상화가 문제를 풀지 않고 **가렸다.**

## 시뮬레이션이 플레이어를 밀어냈다

마인크래프트의 재미는 **실제 오브젝트와의 상호작용**이다. 그런데 이 모드가 만든 것은 대부분 플레이어가 볼 수도 만질 수도 없는 숫자였다 — 사기, 배고픔, 수용력, 생산율, 방어 등급.

증거: 이 프로젝트에서 플레이어가 그 시뮬레이션과 상호작용한 유일한 경우는 **디버깅할 때**였다.

## 사실성이 밸런스를 불가능하게 만들었다

각각은 합리적인데, 곱해지면 잠긴다. 게임 테스트에서 나온 교착들:

| 증상 | 원인 |
|---|---|
| 마을이 전멸 | 편입 주민이 전부 같은 나이 → 한 덩어리로 늙음 |
| 농부 둘, 밀 4천, 통나무 0 | 배정이 일방통행 — 농부가 된 뒤엔 나무꾼이 못 됨 |
| 인구 3에서 정지 | 식량 수용력 = 인구. 여유 0 → 출산 0 |
| 최소 설정이 멸망 | 도로가 없으면 집 부지가 없고, 집이 없으면 침대가 안 늘음 |
| 주민 3명이 습격에 전멸 | 위협이 마을 규모를 안 봄 |

다섯 개 전부 **서로 곱해지는 규칙들** 때문이었다. 하나를 고치면 다음이 드러났다.

## 남길 가치가 있었던 것

실패가 아니었다. 이것들은 살아남는다.

- **격자 측량** — 지면과 건물을 읽어 셀을 분류한다. 여러 번 고쳐서 이제 정확하다
- **건설 파이프라인** — 계획 → 동결 → 순수 함수 전개 → 한 블록씩 배치
- **생성기들** — 오두막, 도로, 성벽. 지형 규칙과 문과 디딤돌까지
- **도구가 부재를 설명해야 한다** — 이 프로젝트에서 가장 비싸게 배운 것

## 가장 비싼 교훈

**"아무 일도 안 일어난다"는 관측에는 늘 설명이 둘 이상 있다.**

이 프로젝트에서 최소 여덟 번 반복됐다. 격자가 0% 빈칸(측량이 마을 광장만 덮었다), 측량이 안 바뀜(자기 판정을 건너뜀), 성벽이 24개에서 멈춤(op 정렬이 뒤섞기였다), 문이 7개인데 땅에는 0개(완료된 작업을 버려서 재생할 게 없었다), 집이 안 지어짐(반경이 광장 크기였다), 통나무가 없음(벨 사람이 없었다).

**매번 출력이 멀쩡해 보였다.** 도구가 자기가 무엇을 **안 했는지** 말하게 만들기 전까지는 아무것도 알 수 없었다.

새 설계에서도 이건 유효하다. 시뮬레이션이 없어도 건설은 여전히 조용히 멈출 수 있다.
